## Reported bugs

### "Everyone was stuck: nobody could move or shoot"

I couldn't reproduce the freeze on the host PC, so these are the two likely causes. Both are now fixed:

1. **Clicking in the server's console window (Windows QuickEdit).** Selecting text in the console pauses every write to it. The server logged each player's connect and disconnect, so the next log line froze the *whole* server until someone pressed a key in that window. This fits "everyone froze at once."
   *Fix:* the server turns QuickEdit off at startup, and logging now runs on a background thread through a queue.
2. **One slow client blocking the game.** The game loop waited for every socket to accept each update before running the next tick. Uvicorn's send waits when a client's buffer is full, so a device on weak Wi-Fi could stall everyone.
   *Fix:* each connection has its own sender that always sends only the newest state, and the game loop never waits on a socket. A client that can't take data for 5 s is disconnected; it reconnects automatically and gets its player back.

Also fixed: on Windows the loop only reached about 22 updates per second because of coarse sleep timing. Ticks are now scheduled against absolute deadlines and run at a steady 30/s.

If it ever happens again, check `server.log` next to `server.py` for `Game loop stalled …` or `Dropping player …` lines.

### "Players moved on their own, as if a key was stuck"

1. **Lost key releases.** The browser only sent key *changes*, so a key release lost to a window switch, the right-click menu, or a Cmd/Ctrl/Alt shortcut left the key "held" forever.
   *Fix:* the client releases all keys on blur, hidden tab, context menu, and modifier keys. It also re-sends the full key state every 250 ms, and the server releases keys after 1 s with no input.
2. **Ghost players after a Wi-Fi hiccup.** The browser reconnected before the server noticed the old connection had died. The server refused the reconnect ("session expired"), and the old player stayed in the game running with its last keys.
   *Fix:* a reconnect carrying the right session token takes over the player and closes the stale connection; held keys are cleared.

## Follow-up after the first playtest

- **Slower game:** movement speed is now 180 (down from 260). The fire cooldown was briefly 0.75 s,
  which felt too slow, so it is back to 0.5 s.
- **Soldier characters instead of circles.** Players are drawn as standing soldiers: head with a
  helmet, a team-coloured body, legs, and a rifle held in both hands. They face left or right
  with the aim, the rifle swivels to the exact aim angle, and the legs stride and the body bobs
  while walking (driven by the distance actually moved, so they stop when the player stops).
  Because the figure is taller than the old circle, bullets now hit a vertical capsule from head
  to feet (`hitbox_half_height` = 8, so 1.6× taller and the same width). Wall collision still
  uses the round body. Bullets fired inside a spawn now stop further from the zone's top and
  bottom edges, so the taller hitbox of an enemy standing just outside can't be reached from
  inside the spawn.
- **"Page loads but JOIN does nothing" and a "phantom" player in the admin list.** The server sent no
  caching instructions, so browsers that had played the previous version kept using its cached
  `index.html` and scripts for hours. Those old scripts crashed on the new server's first message.
  The join itself still reached the server, so the player was created (the phantom KING KONG the
  admin saw), but the page never moved past the name screen. This happened whether the server was
  started with `python server.py` or with `uvicorn`; uvicorn only seemed to work because the
  browsers had refreshed by then. It was reproduced in Chrome by loading the old version and then
  the new server with the same browser profile.
  *Fix:* every page, script and image is now served with `Cache-Control: no-cache`, so browsers
  always check for a newer version (unchanged files come back as a cheap 304). A device that still
  holds files cached *before* this fix may need one hard refresh (Ctrl+F5, or clearing the site
  data on a phone).

- **Two more maps: CastleBlack and TheNorth.** CastleBlack has Team B's room at the top centre and
  Team A's at the bottom centre; TheNorth has Team B top-right and Team A bottom-left. Their walls
  were extracted from the images (outline detection, then filled and split into rectangles, with
  the text labels left out) and checked against the art with `?debug=1`. In TheNorth, the thin
  outline next to Team A's room encloses two pockets too narrow to walk into, so that area is one
  solid block. Every open area of both maps is reachable from both spawns.

## Adding a map

Create `Maps/<Name>/` containing the image and a `map.json`. All coordinates are in **image pixels**:

```json
{
  "name": "Galadriel",
  "image": "Map.jpg",
  "image_size": [2048, 2048],
  "world_size": [1600, 900],
  "walls": [[x, y, width, height], ...],
  "spawn_zones": [[x, y, width, height], [x, y, width, height]]
}
```

- `walls`: solid rectangles. Include the outer border; an L-shaped wall is two rectangles.
- `spawn_zones`: one per team, in `TEAMS` order (first = TEAM A).
- To check alignment, open `http://localhost:8000/?debug=1`; it draws the collision rectangles over the art.
- To validate every map, run `python -m pytest tests/test_maps.py`. It checks that the map loads, that a full team fits in each spawn, and that every open area is reachable.

## How this was tested

- **Automated tests: 55 passing.** New tests cover mid-match joining, map selection, key release on timeout, reconnect takeover, a stalled client not blocking others, and validation of every map.
- **Stress test** (`tools/stress_test.py`), 14 players against a live server: a steady 30 updates per second (max gap under 100 ms). A client that stopped reading was dropped without affecting anyone else; a client whose connection was cut got its player back; the mid-match joiner played; the 15th join was refused; kills and respawns happened.
- **Real Chrome** (Playwright): lobby preview, the map filling the screen, hearts, WASD and arrow keys moving and stopping, release on window blur, a silent client stopping, hold-to-fire at 2 shots/s, mid-match joining, and admin map locking.

To rerun the stress test, start the server with a known password, then:

```bash
python tools/stress_test.py --password <admin password> --seconds 60
```
